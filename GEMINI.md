# agent-skills

Это проект agent-skills — коллекция инженерных навыков промышленного уровня для ИИ-агентов кодирования.

## Структура проекта

```
skills/       → Основные навыки (по одному файлу SKILL.md в каждой директории)
agents/       → Повторно используемые роли (персоны) агентов (reviewer, worker, researcher, oracle)
hooks/        → Хуки жизненного цикла сессии
prompts/      → Сценарии и шаблоны для оркестрации (parallel-review, parallel-research, review-loop)
references/   → Дополнительные чек-листы (производительность, безопасность, доступность, git-conventions)
docs/         → Руководства по настройке и практические задания для студентов
```

## Навыки по этапам (Phases)

**Определение (Define):** spec-driven-development
**Разработка (Build):** frontend-ui-engineering, dnote
**Проверка (Verify):** debugging-and-error-recovery
**Ревью (Review):** code-review-and-quality, performance-optimization, security-and-hardening, humanizer
**Поставка (Ship):** ci-cd-and-automation, git-conventions

## Соглашения (Conventions)

- Каждый навык находится в `skills/<имя>/SKILL.md`
- Раздел YAML frontmatter должен содержать поля `name` и `description`
- Описание (`description`) начинается с того, что делает навык (в третьем лице), после чего следуют условия триггера («Используй, когда...»)
- Каждый навык содержит разделы: Overview (Обзор), When to Use (Когда использовать), Process/Workflow (Процесс/Рабочий процесс), Common Rationalizations (Распространенные оправдания), Red Flags (Красные флаги), Verification (Проверка)
- Все промпты, чеклисты и инструкции, адресованные тебе (ИИ-агенту), пишутся строго на русском языке в **единственном числе** («ты-форма»).

## Команды (Commands)

- Проект не содержит исполняемого кода приложения.
- Валидация: Проверь, чтобы все файлы SKILL.md имели корректный YAML frontmatter с полями `name` и `description`.
- Проверка адресации: При анализе или редактировании файлов убедись, что все обращения к агенту написаны во втором лице единственного числа (например, «Используй», «Сделай», «Проверь»).

## Границы (Boundaries)

- Всегда: Придерживайся структуры шаблонов в директории `skills/` при добавлении новых навыков.
- Всегда: Пиши краткие, понятные отчеты и комментарии к выполняемым задачам.
- Никогда: Не добавляй новые навыки, состоящие из общих абстрактных советов. Каждый навык должен описывать конкретный пошаговый процесс.
- Никогда: Не дублируй логику между навыками — ссылайся на другие файлы в `skills/` или `references/`.
