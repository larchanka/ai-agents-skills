# AGENTS.md

Этот файл содержит руководство для ИИ-агентов кодирования (Claude Code, Cursor, Copilot, Antigravity и др.) при работе с кодом в этом репозитории.

## Обзор репозитория

Коллекция навыков (skills), предназначенная для старших инженеров-разработчиков (senior software engineers). Навыки представляют собой готовые пакеты инструкций и скриптов, расширяющие возможности Клода и твоих ИИ-агентов.

## Интеграция с агентами

ИИ-агент использует **модель выполнения, управляемую навыками** (skill-driven execution model), которая опирается на инструмент `skill` и директорию `/skills` этого репозитория.

### Основные правила

- Если задача соответствует какому-либо навыку, ты ОБЯЗАН его вызвать.
- Навыки расположены в `skills/<имя-навыка>/SKILL.md`.
- Никогда не выполняй реализацию напрямую, если применим какой-либо навык.
- Всегда в точности следуй инструкциям навыка (не применяй их частично).

### Сопоставление намерений с навыками (Intent → Skill Mapping)

Агент должен автоматически сопоставлять намерения пользователя с навыками:

- Новая функциональность / фича → `spec-driven-development`, затем `incremental-implementation`, `test-driven-development`
- Планирование / декомпозиция задач → `planning-and-task-breakdown`
- Баг / сбой / неожиданное поведение → `debugging-and-error-recovery`
- Ревью кода → `code-review-and-quality`
- Рефакторинг / упрощение → `code-simplification`
- Проектирование API или интерфейсов → `api-and-interface-design`
- Работа с UI → `frontend-ui-engineering`
- Редактирование и гуманизация текста → `humanizer`
- Управление заметками и знаниями → `dnote`

### Сопоставление жизненного цикла (Неявные команды)

ИИ-агент не поддерживает слэш-команды вида `/spec` или `/plan`.

Вместо этого агент должен внутренне следовать следующему жизненному циклу:

- ОПРЕДЕЛЕНИЕ (DEFINE) → `spec-driven-development`
- ПЛАНИРОВАНИЕ (PLAN) → `planning-and-task-breakdown`
- СБОРКА (BUILD) → `incremental-implementation` + `test-driven-development`
- ПРОВЕРКА (VERIFY) → `debugging-and-error-recovery`
- РЕВЬЮ (REVIEW) → `code-review-and-quality`
- ПОСТАВКА (SHIP) → `shipping-and-launch`

### Модель выполнения

Для каждого запроса:

1. Определи, применим ли какой-либо навык (даже если вероятность составляет 1%).
2. Вызови соответствующий навык с помощью инструмента `skill`.
3. Строго следуй рабочему процессу навыка.
4. Переходи к реализации только после того, как будут выполнены требуемые шаги (спецификация, план и т. д.).

### Борьба с самооправданиями (Anti-Rationalization)

Следующие мысли неверны и должны игнорироваться:

- «Эта задача слишком мала для применения навыка»
- «Я могу просто быстренько реализовать это сам»
- «Сначала я соберу контекст»

Правильное поведение:

- Всегда сначала проверяй наличие и используй навыки.

## Оркестрация: роли (personas), навыки (skills) и команды (commands)

Этот репозиторий состоит из трех компонуемых уровней. У них разные задачи, и их не следует путать:

- **Навыки** (`skills/<имя>/SKILL.md`) — рабочие процессы с шагами и критериями выхода. Отвечают на вопрос *«Как?»*. Обязательные этапы при совпадении намерений.
- **Роли** (`agents/<роль>.md`) — роли с определенной перспективой и форматом вывода. Отвечают на вопрос *«Кто?»*.
- **Слэш-команды** (`prompts/*.md`) — пользовательские точки входа. Отвечают на вопрос *«Когда?»*. Уровень оркестрации.

Правило композиции: **пользователь (или слэш-команда) является оркестратором. Роли не вызывают другие роли.** Роль может вызывать навыки.

Единственный шаблон оркестрации с участием нескольких ролей, который одобряет данный репозиторий, — это **параллельное разветвление с этапом слияния** (parallel fan-out with a merge step), используемый командой `/ship` для одновременного запуска `code-reviewer`, `security-auditor` и `test-engineer` и синтеза их отчетов. Не создавай роль «роутера», которая сама решает, какую другую роль вызвать; это задача слэш-команд и сопоставления намерений.

См. [agents/README.md](agents/README.md) для получения матрицы решений и [references/orchestration-patterns.md](references/orchestration-patterns.md) для ознакомления с полным каталогом шаблонов.

## Создание нового навыка

### Структура директории

```
skills/
  {skill-name}/           # имя директории в формате kebab-case
    SKILL.md              # Обязательно: определение навыка
    scripts/              # Обязательно: исполняемые скрипты
      {script-name}.sh    # Скрипты Bash (предпочтительно)
  {skill-name}.zip        # Обязательно: упаковано для дистрибуции
```

### Соглашения об именовании

- **Директория навыка**: в формате `kebab-case` (например, `web-quality`)
- **SKILL.md**: всегда в верхнем регистре, всегда именно это имя файла
- **Скрипты**: `kebab-case.sh` (например, `deploy.sh`, `fetch-logs.sh`)
- **Zip-архив**: имя должно точно совпадать с директорией: `{skill-name}.zip`

### Формат SKILL.md

```markdown
---
name: {skill-name}
description: {Одно предложение, описывающее суть навыка, после которого следует одно или несколько условий запуска "Используй, когда...". При необходимости включай триггерные фразы, такие как "Разверни мое приложение" или "Проверь логи".}
---

# {Название навыка}

{Краткий обзор того, что делает навык и почему он важен.}

## Как это работает

{Пронумерованный список с описанием рабочего процесса навыка}

Эквивалентные заголовки вроде `Workflow`, `Core Process` или `When to Use` также допустимы, если они четко передают структуру.

### Рекомендации по эффективности контекста

Навыки загружаются по запросу — при запуске загружаются только имя и описание навыка. Полное содержимое `SKILL.md` попадает в контекст только тогда, когда агент решает, что этот навык релевантен. Чтобы минимизировать использование контекста:

- **Держи размер SKILL.md менее 500 строк** — выноси подробные справочные материалы в отдельные файлы.
- **Пиши конкретные описания** — это помогает агенту точно знать, когда активировать навык.
- **Используй прогрессивное раскрытие информации** — ссылайся на вспомогательные файлы, которые считываются только при необходимости.
- **Предпочитай скрипты встроенному коду** — выполнение скрипта не расходует контекст (его расходует только вывод скрипта).
- **Ссылки на файлы работают на один уровень вглубь** — ссылайся напрямую из SKILL.md на вспомогательные файлы.

### Требования к скриптам

- Используй шебанг `#!/bin/bash`.
- Используй `set -e` для быстрого завершения при ошибках.
- Пиши статусные сообщения в stderr: `echo "Сообщение" >&2`.
- Пиши машиночитаемый вывод (JSON) в stdout.
- Включай перехватчик (trap) для очистки временных файлов.
- Ссылайся на путь к скрипту как `/mnt/skills/user/{skill-name}/scripts/{script}.sh`.

### Создание Zip-пакета

После создания или обновления навыка:

```bash
cd skills
zip -r {skill-name}.zip {skill-name}/
```

### Установка для конечного пользователя

Документируй два метода установки для пользователей:

**Claude Code:**
```bash
cp -r skills/{skill-name} ~/.claude/skills/
```

**claude.ai:**
Добавь навык в базу знаний проекта или вставь содержимое `SKILL.md` прямо в диалог.

Если навыку требуется доступ к сети, инструктируй пользователей о необходимости добавить обязательные домены в `claude.ai/settings/capabilities`.
