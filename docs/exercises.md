# Практические упражнения для студентов (Student Exercises)

Данные упражнения помогут тебе на практике закрепить навыки совместной работы с ИИ-помощниками, научиться правильно делегировать задачи специализированным агентам и контролировать рабочий процесс с помощью спецификаций и чек-листов.

---

## Упражнение 1: Отладка и устранение ошибок (Debugging & Error Recovery)

### Цель:
Научиться использовать навык `debugging-and-error-recovery` для безопасного поиска и исправления багов в существующем коде через написание воспроизводящих тестов.

### Подготовка:
Создай файл `src/math.js` со следующей функцией расчета скидок, которая содержит логическую ошибку и падает при определенных условиях:

```javascript
// Функция расчета итоговой цены со скидкой
function calculateDiscountedPrice(price, discountPercentage) {
  if (discountPercentage > 100) {
    throw new Error("Скидка не может быть больше 100%");
  }
  
  // Логическая ошибка: нет проверки на отрицательные значения
  // А также потенциальная ошибка деления на ноль, если цена передана как строка или пустая
  const discountAmount = price * (discountPercentage / 100);
  return price - discountAmount;
}

module.exports = { calculateDiscountedPrice };
```

### Задание:
1. Запусти ИИ-агента в режиме планирования или чата.
2. Отправь агенту инструкцию, побуждающую использовать нужный навык. **Обрати внимание: промпт написан строго в единственном числе («ты-форма»)**.

> **Промпт для ИИ-агента:**
> «В файле `src/math.js` есть баги. Используй навык `debugging-and-error-recovery`. Сначала напиши тесты в `tests/math.test.js`, которые воспроизводят падение или некорректное поведение (например, при передаче отрицательных чисел, некорректных типов данных или пустых значений). Затем исправь функцию так, чтобы все тесты успешно проходили. Не приступай к исправлению кода, пока не напишешь тесты.»

3. Убедись, что агент:
   - Создал тесты и запустил их, зафиксировав падение.
   - Описал причину бага.
   - Предложил минимальное и безопасное исправление.
   - Запустил тесты заново и подтвердил прохождение.

## Упражнение 2: Разработка новой фичи по спецификации (Spec-Driven Development)

### Цель:
Пройти полный жизненный цикл разработки новой функциональности: от сбора требований до реализации, без написания кода «вслепую».

### Задание:
Тебе нужно добавить в проект простую систему управления задачами (Todo List) с поддержкой приоритетов (`low`, `medium`, `high`).

1. Создай пустую папку проекта и инициализируй её (`npm init -y`).
2. Обратись к ИИ-агенту для составления спецификации.

> **Промпт для ИИ-агента:**
> «Я хочу создать модуль управления задачами Todo Manager на Node.js. Задачи должны содержать текст, статус выполнения и приоритет (low, medium, high). Используй навык `spec-driven-development`. Напиши структурированную спецификацию. Спроси меня об открытых вопросах и предположениях. Не пиши код и план реализации, пока я не утвержу спецификацию.»

3. Проведи ревью спецификации, которую сгенерировал агент:
   - Проверь, все ли граничные случаи учтены (например, валидация приоритетов).
   - Ответь на вопросы агента и внеси правки, если нужно.
   - Напиши агенту: «Спецификация утверждена. Подготовь план реализации и список задач `task.md`».
4. Дождись формирования `task.md`.
5. Дай команду агенту приступить к выполнению: «Начинай реализацию по списку задач, используя навыки `incremental-implementation` и `test-driven-development`. Отмечай прогресс в `task.md`».

## Упражнение 3: Командное ревью и оформление коммитов (Code Review & Git Conventions)

### Цель:
Освоить проверку качества кода с помощью агента-ревьюера и научиться оформлять коммиты в соответствии с принятыми в индустрии стандартами.

### Задание:
Возьми код, написанный во 2-м упражнении, и проведи его аудит.

1. Запусти специализированного агента-ревьюера (`agents/reviewer.md`) или отправь промпт в чат.

> **Промпт для ИИ-агента:**
> «Проведи ревью кода модуля Todo Manager, который мы создали в предыдущем шаге. Используй навык `code-review-and-quality` и чеклист `references/git-conventions.md`. Укажи на возможные проблемы с безопасностью, производительностью, стилем кодирования и соблюдением архитектурных границ. Напиши отчет в виде списка замечаний с примерами исправлений.»

2. Ознакомься с отчетом ревьюера.
3. Попроси агента исправить замечания: «Исправь замечания ревьюера в кодовой базе. Напиши тесты для проверки исправлений».
4. Когда код будет готов, попроси агента подготовить коммит по всем правилам.

> **Промпт для ИИ-агента:**
> «Изучи изменения, которые мы внесли для исправления замечаний ревьюера. Подготовь сообщение коммита на английском языке строго по стандарту Conventional Commits, описанному в `references/git-conventions.md`. Используй повелительное наклонение в заголовке.»

5. Убедись, что сгенерированное сообщение выглядит корректно (например, `fix(todo): validate task priority values before saving`), скопируй его и сделай коммит в свой репозиторий.
