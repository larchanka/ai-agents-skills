# Настройка Model Context Protocol (MCP) для ИИ-агентов

**Model Context Protocol (MCP)** — это открытый стандарт, разработанный Anthropic, который позволяет ИИ-моделям и агентам безопасно подключаться к внешним источникам данных и инструментам: базам данных, веб-API, локальным файловым системам и сторонним сервисам (GitLab, Slack и др.).

Благодаря MCP твой ИИ-помощник может не просто писать код, но и напрямую читать схемы таблиц БД, отправлять сообщения в Slack, создавать коммиты в GitLab или искать информацию в сети.

---

## Как это устроено

Схема взаимодействия выглядит следующим образом:

```
┌─────────────┐        MCP Protocol        ┌─────────────┐
│  ИИ-клиент  │ ─────────────────────────> │ MCP Server  │ ──> [База данных]
│ (Claude/IDE)│ <───────────────────────── │ (Postgres)  │ <── [Файловая система]
└─────────────┘                            └─────────────┘
```

ИИ-клиент считывает файл конфигурации, запускает указанные в нем серверы MCP как дочерние процессы и получает список доступных инструментов (tools).

---

## Настройка файлов конфигурации

Конфигурационный файл содержит список серверов и параметры их запуска. Путь к файлу зависит от используемого клиента:

- **Claude Desktop (macOS)**: `~/Library/Application Support/Claude/claude_desktop_config.json`
- **Claude Desktop (Windows)**: `%APPDATA%\Claude\claude_desktop_config.json`
- **Claude Code (Глобальный)**: `~/.claude/config.json`
- **Cursor / VS Code (плагины MCP)**: Настраивается через графический интерфейс настроек.

---

## Примеры конфигурации серверов MCP

Ниже приведен пример стандартного файла `claude_desktop_config.json`, в котором настроены несколько популярных серверов:

```json
{
  "mcpServers": {
    "postgresql": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-postgres",
        "postgresql://username:password@localhost:5432/my_database"
      ]
    },
    "gitlab": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-gitlab"
      ],
      "env": {
        "GITLAB_PERSONAL_ACCESS_TOKEN": "your-gitlab-token-here",
        "GITLAB_API_URL": "https://gitlab.example.com/api/v4"
      }
    },
    "slack": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-slack"
      ],
      "env": {
        "SLACK_BOT_TOKEN": "xoxb-your-slack-bot-token"
      }
    },
    "web-search": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-brave-search"
      ],
      "env": {
        "BRAVE_API_KEY": "your-brave-search-key"
      }
    }
  }
}
```

> [!IMPORTANT]
> При использовании команды `npx` убедись, что Node.js установлен в твоей системе и доступен глобально. Для некоторых сред разработки (например, Cursor на macOS) может потребоваться указать полный абсолютный путь к `npx` или `node` (например, `/opt/homebrew/bin/npx`).

## Детальная настройка популярных серверов

### 1. PostgreSQL (Работа с БД)
Этот сервер дает агенту возможность просматривать структуру таблиц, выполнять SQL-запросы, анализировать данные и оптимизировать медленные транзакции.
- **Установка**: Автоматически через `npx` или локально `npm install -g @modelcontextprotocol/server-postgres`.
- **Строка подключения**: Укажи правильный URI к базе данных, включая логин, пароль, хост, порт и имя БД.

### 2. GitLab / GitHub (Управление кодом и задачами)
Позволяет агенту искать код в репозитории, читать и оставлять комментарии к тикетам и Merge Requests, получать логи упавших пайплайнов.
- **Токен**: Необходим Personal Access Token (PAT) с правами доступа к API.
- **Параметры**: Если используется self-hosted инстанс GitLab, обязательно передай переменную `GITLAB_API_URL`.

### 3. Slack (Уведомления)
Используется для отправки отчетов о проделанной работе, уведомлений об ошибках сборки или запросов на ревью.
- **Настройка**: Требуется создать Slack App воркспейса и выдать ему необходимые Bot Scopes (`chat:write`, `channels:read`).

## Инструкции для ИИ-агента по использованию MCP (Чеклист)

Когда ты (ИИ-агент) используешь MCP-инструменты в своей работе, следуй этим правилам:

- [ ] **Не навреди:** Будь предельно осторожен при выполнении модифицирующих действий (SQL-запросы `UPDATE`, `DELETE`, создание веток в Git, отправка сообщений). Никогда не выполняй деструктивные действия без явного одобрения человека.
- [ ] **Сначала исследуй схему:** Прежде чем делать SQL-запросы, всегда считывай схему таблиц, чтобы знать точные имена колонок и типы данных. Не пытайся угадать структуру БД.
- [ ] **Оптимизируй лимиты:** При выборке данных из таблиц или поиске по API GitLab всегда ограничивай размер выдачи (`LIMIT`), чтобы не перегружать контекст и память.
- [ ] **Логируй свои действия:** Если ты отправил уведомление в Slack или изменил статус задачи в GitLab, обязательно сообщи об этом человеку в своем ответе.

## Решение распространенных проблем (Troubleshooting)

1. **Сервер MCP не запускается (Не найден путь к npx)**
   - *Проблема*: В логах клиента ошибка вида `spawn npx ENOENT` или аналогичная.
   - *Решение*: Замени `"npx"` в поле `"command"` на полный путь к исполняемому файлу. Узнать путь можно в терминале с помощью команды `which npx` (macOS/Linux) или `where npx` (Windows). Например: `"/opt/homebrew/bin/npx"`.

2. **Ошибки авторизации (Invalid Token)**
   - *Проблема*: Сервер запускается, но инструменты выдают ошибку 401 или 403.
   - *Решение*: Проверь правильность токенов в блоке `"env"`. Убедись, что срок действия токена в GitLab/Slack не истек и у него выбраны нужные права (scopes).

3. **Блокировка базы данных / Таймауты**
   - *Проблема*: Агент зависает при попытке сделать SELECT запрос.
   - *Решение*: Убедись, что база данных запущена локально или сетевые доступы (файрвол) разрешают входящие подключения с твоего компьютера.
