# Руководство по настройке и использованию (Setup & Usage Guide)

Добро пожаловать в коллекцию навыков (skills), системных промптов и конфигураций агентов. Эти инструменты созданы для того, чтобы помочь тебе эффективно работать в связке с ИИ-помощниками (Claude Code, Cursor, OpenCode, claude.ai и др.).

Данное руководство поможет настроить рабочее окружение и научит твоего ИИ-ассистента правильно применять эти материалы.

---

## Структура репозитория

Инструменты разделены на три ключевых уровня:

1. **Навыки (Skills)** (`/skills/`) — готовые пакеты инструкций и скриптов, расширяющие возможности ИИ. Каждый навык расположен в своей папке и описывает рабочий процесс (*«Как делать?»*).
2. **Агенты (Agents)** (`/agents/`) — специализированные системные роли (персоны) с определенным фокусом (*«Кто делает?»*).
3. **Промпты и сценарии (Prompts)** (`/prompts/`) — шаблоны запросов и оркестрации для сложных сценариев работы (*«Когда делать?»*).

Также в репозитории содержатся:
- `/references/` — справочные чек-листы и правила (производительность, безопасность, соглашения по Git).
- `/docs/` — обучающие материалы, руководства по настройке и практические упражнения для студентов.

---

## Настройка ИИ-инструментов

### 1. Использование с Claude Code

Claude Code автоматически подгружает навыки и роли, если они скопированы в соответствующие директории настроек.

#### Установка навыков (Skills):
Скопируй папки навыков из директории `skills/` в домашнюю директорию настроек Claude Code:
```bash
cp -r skills/* ~/.claude/skills/
```

#### Установка агентов (Agents):
Скопируй файлы конфигураций агентов из директории `agents/` в домашнюю директорию настроек:
```bash
cp -r agents/* ~/.claude/agents/
```

После этого ты сможешь вызывать специализированных агентов или запускать навыки непосредственно из терминала.

---

### 2. Использование в claude.ai (Раздел Projects / Проекты)

Если ты пользуешься веб-интерфейсом Claude.ai (подписка Pro или Team), лучшим решением будет создание **Проекта (Project)**:

1. Создай новый проект в интерфейсе Claude.ai.
2. Добавь в Базу знаний (Knowledge Base) проекта ключевые файлы из этого репозитория:
   - `AGENTS.md` — главный файл оркестрации и правил.
   - Нужные тебе файлы из папки `/skills/` (например, `spec-driven-development/SKILL.md` или `debugging-and-error-recovery/SKILL.md`).
   - Файлы из папки `/references/` для контроля качества кода.
3. Скопируй содержимое файла `CLAUDE.md` в раздел **Custom Instructions** проекта.

---

### 3. Использование в Cursor / VS Code (с поддержкой правил проекта)

Для редакторов кода (например, Cursor), которые считывают локальные файлы инструкций:

1. Помести файл `.cursorrules` в корень своего рабочего проекта. Внутри него сошлись на правила из `AGENTS.md` и `CLAUDE.md`.
2. Добавь файлы `AGENTS.md` и `CLAUDE.md` в корень проекта, чтобы ИИ-ассистент считывал их при индексации кодовой базы.
3. Во время общения с ассистентом через чат (Ctrl+L / Cmd+L) или инлайн-инструкции (Ctrl+K / Cmd+K) ты можешь явно упоминать файлы навыков (например, `@SKILL.md` из папки соответствующего навыка), чтобы ИИ следовал описанному там процессу.

## Как это работает: Модель выполнения, управляемая навыками (Skill-Driven Execution)

Важнейшее правило этого репозитория — **ИИ-агент не должен импровизировать, если для текущей задачи существует готовый навык**.

Когда ты даешь задачу ИИ-агенту (например, исправить баг, сверстать UI или спроектировать API), агент должен выполнить следующие действия:
1. Проанализировать твой запрос и проверить папку `/skills/`.
2. Если задача совпадает с назначением навыка (даже частично), агент считывает соответствующий файл `SKILL.md`.
3. Агент строго следует описанному в навыке рабочему процессу (например, сначала составляет спецификацию, затем делает план, пишет тесты, проверяет код линтером и только потом сдает работу).

### Золотое правило общения с агентом
Обращение к ИИ-агенту в промптах и инструкциях всегда формулируется в **единственном числе** (на «ты»).
- **Правильно**: *«Используй навык spec-driven-development для создания спецификации. Проверь код на ошибки перед коммитом.»*
- **Неправильно**: *«Используйте навык... Проверьте код...»*

Это помогает ИИ-агенту точнее ассоциировать себя с выполняемой ролью и исключает путаницу в контексте.

## Советы по эффективной работе

1. **Не допускай пропусков этапов**: Если навык требует сначала написать спецификацию (как в `spec-driven-development`), не разрешай агенту сразу писать код. Контролируй выполнение каждого шага.
2. **Используй чек-листы**: При сдаче работы агентом проси его проверить код по чек-листам из папки `references/` (например, `@security-checklist.md` или `@performance-checklist.md`).
3. **Оркестрируй роли**: Для сложных задач используй цепочки агентов. Например, пусть один агент (`worker.md`) пишет код, а другой (`reviewer.md`) проводит его ревью по правилам из `references/git-conventions.md`.
