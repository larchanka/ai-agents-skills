## Моделирование угроз (Начни отсюда)

Перед выбором защитных механизмов потрать пять минут на то, чтобы подумать как атакующий:

- [ ] Границы доверия размечены (запросы, загрузка файлов, вебхуки, сторонние API, вывод LLM).
- [ ] Конфиденциальные ресурсы определены (ключи доступа, персональные данные (PII), платежные данные, действия администратора, финансовые транзакции).
- [ ] Проведен анализ STRIDE для каждой границы (Spoofing — подмена, Tampering — фальсификация, Repudiation — отрицание авторства, Information disclosure — разглашение информации, DoS — отказ в обслуживании, Elevation of privilege — повышение привилегий).
- [ ] Описаны сценарии злоупотребления (abuse cases) рядом с пользовательскими сценариями (use cases): «как бы я мог использовать это во вред?».

## Проверки перед коммитом

- [ ] Отсутствуют секреты в коде (`git diff --cached | grep -i "password\|secret\|api_key\|token"`).
- [ ] Файл `.gitignore` содержит правила для: `.env`, `.env.local`, `*.pem`, `*.key`.
- [ ] Файл `.env.example` использует только шаблонные значения (без реальных секретов).

## Аутентификация

- [ ] Пароли хэшируются с помощью bcrypt (≥12 раундов), scrypt или argon2.
- [ ] Файлы cookie сессий настроены с флагами: `httpOnly`, `secure`, `sameSite: 'lax'`.
- [ ] Настроено время жизни сессии (разумный параметр max-age).
- [ ] Ограничена частота запросов (rate limiting) на эндпоинте входа (например, ≤10 попыток за 15 минут).
- [ ] Токены сброса пароля ограничены по времени (≤1 час) и являются одноразовыми.
- [ ] Настроена блокировка учетной записи после повторных неудачных попыток входа (опционально, с уведомлением пользователя).
- [ ] Поддерживается многофакторная аутентификация (MFA) для чувствительных операций (опционально, но рекомендуется).

## Авторизация

- [ ] Каждая защищенная конечная точка (endpoint) проверяет аутентификацию.
- [ ] При каждом доступе к ресурсу проверяется владелец или роль (предотвращает IDOR — небезопасные прямые ссылки на объекты).
- [ ] Административные эндпоинты требуют проверки роли администратора.
- [ ] Ключи API ограничены минимально необходимыми правами доступа.
- [ ] Токены JWT валидируются (подпись, срок действия, издатель).

## Валидация ввода

- [ ] Весь пользовательский ввод валидируется на границах системы (маршруты API, обработчики форм).
- [ ] Валидация использует белые списки (allowlists), а не черные (denylists).
- [ ] Ограничена длина строк (минимальная / максимальная).
- [ ] Валидируются числовые диапазоны.
- [ ] Форматы email, URL и дат валидируются с использованием проверенных библиотек.
- [ ] Загрузка файлов: типы файлов строго ограничены, размер лимитирован, содержимое проверяется.
- [ ] SQL-запросы параметризованы (никакой конкатенации строк).
- [ ] Вывод HTML кодируется (используй автоэкранирование шаблонизатора/фреймворка).
- [ ] URL-адреса валидируются перед перенаправлением (предотвращает открытый редирект — open redirect).
- [ ] Запросы к внешним ресурсам на стороне сервера (SSRF) валидируются по белому списку; приватные/зарезервированные IP-адреса блокируются.

## Заголовки безопасности

```
Content-Security-Policy: default-src 'self'; script-src 'self'
Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
X-XSS-Protection: 0  (отключено, полагайся на CSP)
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=()
```

## Конфигурация CORS

```typescript
// Ограничительная конфигурация (рекомендуется)
cors({
  origin: ['https://yourdomain.com', 'https://app.yourdomain.com'],
  credentials: true,
  methods: ['GET', 'POST', 'PUT', 'PATCH', 'DELETE'],
  allowedHeaders: ['Content-Type', 'Authorization'],
})

// НИКОГДА не используй в продакшне:
cors({ origin: '*' })  // Разрешает любой источник
```

## Защита данных

- [ ] Чувствительные поля исключены из ответов API (`passwordHash`, `resetToken` и т.д.).
- [ ] Чувствительные данные не логируются (пароли, токены, полные номера кредитных карт).
- [ ] Персональные данные (PII) шифруются при хранении (если требуется по регламенту).
- [ ] Используется HTTPS для всех внешних взаимодействий.
- [ ] Бэкапы баз данных зашифрованы.

## Безопасность зависимостей

```bash
# Аудит зависимостей
npm audit

# Автоматическое исправление, где это возможно
npm audit fix

# Проверка на наличие критических уязвимостей
npm audit --audit-level=critical

# Поддержание зависимостей в актуальном состоянии
npx npm-check-updates
```

**Гигиена цепочки поставок (supply-chain)** (`npm audit` не поймает вредоносные пакеты):
- [ ] Файл lockfile зафиксирован в репозитории; CI устанавливает зависимости через `npm ci` (а не `npm install`).
- [ ] Новые зависимости проверяются (активность поддержки, загрузки, скрипты `postinstall`).
- [ ] Отсутствуют опечатки в именах пакетов (typosquatting) (например, `cross-env` вместо `crossenv`, `react-dom` вместо `reactdom`).

## Безопасность ИИ / LLM

Для любой фичи, вызывающей LLM (чат-боты, суммаризаторы, агенты, RAG):

- [ ] Вывод модели рассматривается как недоверенный — никогда не передавай его напрямую в `eval`/SQL/shell/`innerHTML`/пути к файлам.
- [ ] Предполагай возможность инъекции промпта; права доступа должны проверяться в коде, а не в системном промпте.
- [ ] Секреты, межпользовательские данные и полные системные промпты должны быть исключены из окна контекста.
- [ ] Права доступа инструментов/агента ограничены; деструктивные или необратимые действия требуют подтверждения со стороны пользователя.
- [ ] Установлены лимиты токенов, частоты запросов и глубины рекурсии/циклов (ограничение потребления ресурсов).

## Обработка ошибок

```typescript
// Продакшн: общий текст ошибки, без внутренних деталей
res.status(500).json({
  error: { code: 'INTERNAL_ERROR', message: 'Something went wrong' }
});

// НИКОГДА в продакшне:
res.status(500).json({
  error: err.message,
  stack: err.stack,         // Раскрывает внутренности
  query: err.sql,           // Раскрывает структуру БД
});
```

## Краткий справочник OWASP Top 10

| № | Уязвимость | Предотвращение |
|---|---|---|
| 1 | Недостаточный контроль доступа | Проверки авторизации на каждом эндпоинте, проверка владельца |
| 2 | Сбои шифрования | HTTPS, надежное хэширование, отсутствие секретов в коде |
| 3 | Инъекции | Параметризованные запросы, валидация ввода |
| 4 | Небезопасное проектирование | Моделирование угроз, разработка на основе спецификаций (spec-driven) |
| 5 | Неправильная настройка защиты | Заголовки безопасности, минимальные права доступа, аудит зависимостей |
| 6 | Уязвимые компоненты | `npm audit`, обновление зависимостей, минимизация сторонних пакетов |
| 7 | Сбои идентификации | Надежные пароли, ограничение частоты запросов, управление сессиями |
| 8 | Сбои целостности данных/ПО | Проверка обновлений/зависимостей, подписанные артефакты |
| 9 | Недостаточное логирование | Логирование событий безопасности, исключение секретов из логов |
| 10 | SSRF | Валидация/белые списки URL, ограничение исходящих запросов |

## Краткий справочник OWASP Top 10 для LLM

Для приложений с функциями LLM. См. проект [OWASP GenAI Security Project](https://genai.owasp.org/llm-top-10/).

| ID | Риск | Предотвращение |
|---|---|---|
| LLM01 | Инъекция промпта (Prompt Injection) | Не надейся на системный промпт как на границу защиты; проверяй права доступа в коде |
| LLM02 | Утечка конфиденциальных данных | Не передавай секреты/персональные данные в промпты; фильтруй выводы |
| LLM03 | Уязвимости цепочки поставок | Проверяй модели, датасеты и плагины так же тщательно, как любую зависимость |
| LLM04 | Отравление данных и моделей | Используй доверенные источники моделей, проверяй целостность; проверяй данные RAG и файнтюнинга |
| LLM05 | Некорректная обработка вывода | Относись к выводу модели как к недоверенному; валидируй, параметризуй, кодируй |
| LLM06 | Избыточная автономность (Agency) | Ограничивай права инструментов; требуй подтверждения разрушительных действий |
| LLM07 | Утечка системного промпта | Исходи из того, что системный промпт может утечь; не храни в нем секреты |
| LLM08 | Слабости векторов и эмбеддингов | Разделяй эмбеддинги RAG по пользователям; валидируй документы перед индексацией |
| LLM09 | Галлюцинации и дезинформация | Подтверждай ответы цитатами; проверяй критические заявления; оставляй человека в цикле принятия решений |
| LLM10 | Неограниченное потребление ресурсов | Ограничивай количество токенов, частоту запросов и глубину циклов/рекурсии |
